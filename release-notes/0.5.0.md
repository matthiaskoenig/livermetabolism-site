# Release notes for livermetabolism-site 0.5.0

We are pleased to release the next version of the König Lab website, https://livermetabolism.com. This release replaces the Jekyll build with Astro, moves the deployment to GitHub Pages, and applies a security, quality, and page-weight audit. Visitors see the same pages, URLs, and interactions; what changed is everything underneath.

## Breaking changes
- the site is built with [Astro](https://astro.build/) (static output) and [Vue](https://vuejs.org/) single-file components styled with Tailwind v4; Jekyll, Liquid templates, Bootstrap, Bootswatch, Sass, the hosted Font Awesome kit, and the hand-written page scripts are gone. Anyone editing templates now works in `site/` (`pages/`, `layouts/`, `components/`, `lib/`, `styles/global.css`); Astro's default `src/` is the Python package, so the app lives under `site/`
- the YAML tables moved from `app/_data/` to `data/`, the served files from `app/assets/` to `public/assets/` (same `/assets/...` URLs), and the raster masters to `assets_src/`, which is not served. `src/data.py` (pydantic) stays the schema of record and is mirrored by Zod schemas in `site/lib/schemas.ts`; both run in CI, so a bad edit fails before merge
- the default branch is `main` (renamed from `master`); `develop` is gone. `main` is protected by a ruleset: pull requests only, linear history, squash or rebase merges, required checks `validate` and `build`
- the site deploys to GitHub Pages from `.github/workflows/site.yml` on every merge to `main`, at `https://matthiaskoenig.github.io/livermetabolism-site/` until the domain is attached. The self-hosted nginx path remains: `docker-compose-build.yml` builds `dist/` in a `node:24-alpine` container, `docker-compose.yml` serves it with `nginx:1.31.5-alpine`, `deploy.sh` chains pull, build, and restart on the server
- the tag naming follows sbmlutils: releases are tagged `0.5.0`, not `v0.5.0`, and `release-notes/<version>.md` is the body of the GitHub release
- `js-yaml` 5 parses the data with a YAML 1.2 parser, which requires the continuation lines of multi-line quoted strings to be indented deeper than their key; `data/*.yml` was re-indented accordingly (the parsed content is unchanged, verified against the pydantic loader)

## Features
- every page, URL, and anchor id of the old site is reproduced: homepage with the five research-area sections, projects, publications (with presentations, posters, abstracts), team with alumni timeline, research (software, funding, editors), meetings, news, teaching, CV, impressum, privacy, 404, the sitemap, and the full-text search index at `/search.json`
- list pages render statically; a small `TagFilter` island filters the DOM by research tag and honours `?tag=` links from the homepage; project, news, and person detail modals are native `<dialog>` elements opened by click, keyboard, or deep link (`/people/#person-modal-<id>`), which search results use
- the navbar toggle, cookie banner, site search, and modal router are plain TypeScript in Astro components, so the five light pages ship no framework runtime; Vue hydrates only the tag filters and the hover cards
- icons are an inline SVG sprite built from the Font Awesome Free 6 set by `scripts/fetch-icons.sh`, named by the Font Awesome 4 names the data uses
- the footer states the deployed version and commit, linking to the GitHub release and commit
- a `release` GitHub workflow creates the GitHub release from `release-notes/<tag>.md` when a version tag is pushed

## Security
- a Content-Security-Policy generated by Astro (`security.csp`) with hashes for every inline script and style; no `'unsafe-inline'` anywhere. Allowed third parties are Google Fonts, Google Analytics (loaded only after consent), and YouTube thumbnails and embeds; new hosts must be added in `astro.config.mjs`
- `Permissions-Policy` on the self-hosted nginx, one authority for `X-Frame-Options`/`X-Content-Type-Options` (the host reverse proxy), headers repeated in the asset locations so nginx does not drop them
- news video URLs are validated as YouTube embed URLs by the schema; search results are built from text nodes, never from HTML strings; every data-supplied link goes through a base-path helper with a documented trust boundary
- GitHub Actions on current majors with least-privilege permissions; Dependabot for actions, npm, and uv (TypeScript 7 is ignored until `vue-tsc` and `@astrojs/check` support it)

## Performance
- the four heaviest pages no longer serialise every record into island props: gzipped HTML publications 176 → 101 KB, news 109 → 69 KB, projects 50 → 29 KB, people 60 → 43 KB
- the light pages (teaching, CV, impressum, privacy, 404) ship 2.4 KB of JavaScript instead of 82 KB
- the five decorative homepage backgrounds are 59–79 KB each instead of about 1 MB; two accidental animated thumbnails are single frames; an 868 KB SVG logo became a 6 KB image; card images are capped at 800 px
- 14 unreferenced files (25 MB) removed from the served tree; images carry `decoding="async"`, explicit dimensions where the layout is fixed, and lazy loading; below-the-fold islands hydrate on visibility
- fingerprinted `/_astro/` bundles are cached immutably for a year on the self-hosted nginx, `/assets/` for an hour

## Fixes
- Astro's content layer returns collections sorted by id, not in file order; the loaders inject an `order` field and the data views restore the YAML order, which the homepage sections, software, projects, and funding depend on
- Tailwind's own `.container` utility overrode the site's `.container` rules; the stylesheet declares an explicit layer order
- root-absolute links in the data (theses and slides under `/assets/pdf/`) carry the deploy base path
- the GitHub Pages environment only allowed deployments from `master`, so every deploy after the branch rename failed silently; the policy allows `main`
- three inline images in alumni descriptions and one abstract PDF reference pointed at files that were never served; the validator now also checks `publications.pdf` and `funding.funder_logo`
- the root `favicon.ico` was the pre-brand-mark icon; the web manifest is generated with base-aware icon paths
- the dead `50x.html` error page in the nginx config and an unused `.person-flag` rule are gone

## Development
- `npm run check` runs `astro check` and `vue-tsc`; Vitest covers the schemas against every real data row, the Liquid-parity helpers, the modal router, the tag filter, search scoring, consent, and the icon set (81 tests); Playwright covers every page for console errors and the interactions (modals, deep links, hover cards, tag filter, search shortcuts, consent gating, mobile navbar), locally and under the GitHub Pages base path (24 tests)
- the design spec and the implementation plans of the migration and the audit are in `docs/superpowers/`; `CLAUDE.md` and `README.md` describe the current tree, the data model, the island design, and both deployment paths
