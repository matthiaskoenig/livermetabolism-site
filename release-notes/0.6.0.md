# Release notes for livermetabolism-site 0.6.0

We are pleased to release the next version of the König Lab website, https://livermetabolism.com. This release brings live data to the site: the research page shows the latest release, stars, open issues, and last push of every software package with new "Latest releases" and "Commit activity" sections, and the publications page opens with the citation metrics of the group's Google Scholar profile. Both are refreshed daily without redeploying the site.

## Features
- every software card on the research page carries a stats line with the latest release (linked to the release page), the number of stars, open issues, the time since the last push, the primary language, and the licence; cards whose repository is not on GitHub show no line
- a "Latest releases" section (`/research/#releases`) lists the newest release of every repository from the last two years, with its tag, date, and a plain-text summary of the release notes, followed by a release-history timeline of all recorded releases
- a "Commit activity" section (`/research/#activity`) shows the weekly commits of the last year stacked per repository and a stars chart coloured by language; both sections are linked from the Research menu
- the charts are [Apache ECharts](https://echarts.apache.org/) islands that load only on the research page and only when they scroll into view; tooltips and legends are rendered without inline styles so the Content-Security-Policy stays as strict as before
- the data comes from a daily snapshot: the research page is rendered with the snapshot current at build time, and every visit fetches the current snapshot in the browser and updates the stats lines, the feed, and the charts when it is newer, so the page stays current between deployments. A note states when the data was fetched
- the website itself is listed as software (`livermetabolism.com`, "Source of this website"), so its own releases and commits appear on the page
- the publications page opens with a "Citations" section (`/publications/#scholar`): total citations, h-index, and i10-index with their "since" variants as Google Scholar reports them, the number of publications, a link to the profile, a citations-per-year chart, and a citations-over-time chart that grows by one point per day from this release on; the section is linked from the Publications menu and refreshes in the browser like the GitHub data

## Security
- the snapshot carries text only: release notes are reduced to a plain-text summary of at most 300 characters before they leave the pipeline, every read of the snapshot (in the build and in the browser) is validated against a strict schema, and no snapshot content is ever inserted as HTML
- `connect-src` of the Content-Security-Policy gains `https://raw.githubusercontent.com`, the only new host; no `'unsafe-inline'` was added
- visitors' browsers never contact Google: the Scholar numbers are fetched once a day by the workflow from the public profile page and served from the snapshot branch; the only strings taken from that page are the profile name and URL, validated by the schema
- the data workflow runs with the repository's default token, has `contents: write` only to push the snapshot, and commits to the orphan branch `github-data`, which holds nothing but `github.json`; the site build and deploy never trigger on that branch

## Performance
- the ECharts bundle (185 KB gzipped) is the heaviest asset of the site; it is deferred to the research page and to the moment a chart becomes visible, so no other page and no first paint pays for it. The research page HTML grows from 20 to 28 KB gzipped with the server-rendered feed and stats lines, the publications page by under 1 KB; the refresh scripts are deferred modules
- the snapshot is written minified (78 KB for 11 repositories, 166 releases, 52 weeks of activity each) because the browser fetches it on every research-page view

## Fixes
- the commit activity of a repository whose statistics GitHub is still computing (the `/stats/commit_activity` endpoint answers 202 for a repository pushed to daily, such as this site) is filled from the `/stats/participation` endpoint, which carries the same weekly totals; the derived week dates are checked against a recorded response of the primary endpoint
- the chart palette returned no colour for a language outside the legend; the lookup now wraps correctly
- a repository renamed on GitHub (`libsbgn-python`, now `libsbgnpy`) kept its build-time numbers because the stats line was keyed by GitHub's current name; the line is keyed by the name in `software.yml`, and a build that could not reach the snapshot renders the empty line so the browser can fill it in

## Development
- `scripts/fetch-github.ts` (Node 24, TypeScript, no build step) collects the `repository` URLs of `data/software.yml` (normalised to `owner/name`, deduplicated: two entries share `sbmlutils`), calls the GitHub REST API with retries, transforms the responses into the snapshot shape, and writes `github.json` atomically; run it locally with `GITHUB_TOKEN=$(gh auth token) npm run fetch:github -- github.json`
- `scripts/fetch-scholar.ts` fetches the public Scholar profile page, parses the stats table and the histogram with a small tested parser (recorded page in `tests/fixtures/scholar/`), carries the daily history over from the previous snapshot, and writes `scholar.json`; a blocked request (Google answers 403 to Actions runners now and then) is retried twice and then fails that step without touching the previous snapshot or the GitHub step
- `.github/workflows/github-data.yml` runs both fetches daily at 05:00 UTC and on manual dispatch and commits the snapshots to the `github-data` branch only when they changed
- `site/lib/githubSchema.ts` and `site/lib/scholarSchema.ts` are the Zod schemas of the two snapshots, shared by the pipeline and the site; `site/lib/github.ts` (build-time read with a 10 s timeout and an empty fallback), `site/lib/githubLive.ts` (one memoized browser fetch per page), `site/lib/githubRows.ts` (pure row helpers), `site/lib/githubStats.ts` (stats-line patching), and `site/lib/chartOptions.ts` (chart options) are unit-tested; `echarts` 6 is the only new runtime dependency
- Vitest runs 229 tests, 116 of them new (transformations against recorded API and profile fixtures, the retry logic of both fetches, the schemas, the row helpers, the DOM patching, the chart options); Playwright grows from 24 to 26 tests (the research and publications pages render the live data, the charts hydrate, and no console error occurs)
- the design spec and the implementation plan are in `docs/superpowers/`; `CLAUDE.md` and `README.md` describe the pipeline, the snapshot, the branch, and the text-only rule
