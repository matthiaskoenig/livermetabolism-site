# Release notes for livermetabolism-site 0.9.0

We are pleased to release the next version of the König Lab website, https://livermetabolism.com. This release gives people, publications, projects, software, and news one standard detail view, opened as a modal from every card, row, search result, and node of the network graph.

## Breaking changes
- the per-page modals (`PersonModal`, `ProjectModal`, `NewsModal`) and their inline bodies are gone; a detail is addressed as `#<type>/<id>` (for example `/publications/#publication/Koenig2012_x`). The old `#person-modal-<id>`, `#project-modal-<id>`, and `#news-modal-<id>` links still open the same detail; the list anchors (`#pub-<id>`, `#project-<id>`, `#news-<id>`, `#software-<id>`, `#person-<id>`) still scroll to and highlight the card or row

## Features
- every person, publication, project, software entry, and news item has a standard detail with the same anatomy: image or badge, title, one subtitle line, research-area tags, external links as icons; live figures (citations and open access for a paper; stars, latest release, open issues, and last push for software; publication count and summed citations for a person); the description or abstract with keywords; related items (people, publications, projects, software, news, presentations, posters) as compact rows; and a "show in list" link
- related rows open the next detail inside the same dialog, with a Back button, so one can browse from a person to a paper to its project without leaving the page
- the detail opens from the person cards and avatars, project and news cards, publication titles, software names, search results, and the nodes of the network graph, which now opens the detail in place instead of leaving the page
- news details embed the video where there is one, project details show the full image gallery with its caption
- the research page opens with the Releases and Activity sections above the software list, and the navbar lists Publications before Projects

## Security
- the detail content is prerendered at build time into static fragments on the same origin and adopted as parsed nodes; nothing from a URL or a fetch is inserted as HTML, the type and id from a hash are validated before any request, and the Content-Security-Policy is unchanged

## Performance
- the list pages no longer carry every detail body: the team page shrinks from 44 to 25 KB gzipped, projects from 29 to 22 KB, news from 69 to 30 KB; a detail is fetched once on first open (1–2 KB gzipped for most of them, 17 KB for the largest) and cached
- the page chrome bundle shrinks from 22 to 4 KB because the detail types no longer pull the YAML schemas into every page

## Fixes
- clicking a node of the network graph had stopped opening anything after node dragging landed; the click is now derived from the press and release pair
- the 298 detail fragments are excluded from the sitemap
- the detail modal keeps the keyboard focus inside the dialog when a related row replaces its content, leaves a ⌘/Ctrl-click on a card or row to the browser so it opens in a new tab, and lets the browser's Back step out of a related-row hop instead of opening the same detail again

## Development
- `site/lib/details.ts` builds one `DetailModel` per entity from the data and the three snapshots (`buildRelations` derives the symmetric relations once); `site/components/DetailView.vue` renders it for all types; `site/pages/detail/[type]/[id].astro` emits the fragments as Astro page partials; `site/lib/detailModal.ts` is the shell's router (fetch, cache, stack, hash sync)
- Vitest runs 401 tests (47 new: relations, models, the modal router on happy-dom); Playwright 42 (every trigger, in-modal browsing, deep links, legacy hashes, the network click)
- the design spec and the plan are in `docs/superpowers/`; `CLAUDE.md` describes the detail model, the fragments, the shell, and the hash scheme
