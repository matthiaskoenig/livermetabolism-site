# Release notes for livermetabolism-site 0.12.2

A patch release adding the sbml2cellml converter to the software list, and a command that assembles the group's newsletter from what the repository already records.

## Features
- `sbml2cellml` joins the software packages and the GitHub statistics (#73). It converts between SBML and CellML 2.0 in both directions, validating every conversion with libcellml and checking it by simulation against the SBML test suite and the curated BioModels, so models can move between the two main model description standards instead of being locked into one. Its first release went out on 18 September 2026

## Development
- `npm run newsletter -- <from> <to>` writes one issue of the lab newsletter (#74) from sources the repository already keeps: the daily GitHub and Scholar snapshots, this repository's own history, the release notes of each version, and the data tables diffed across the window. The output is Markdown under `newsletter/`, which sits beside `release-notes/` and is deliberately not part of the website; images are embedded by linking the original resource rather than copying anything in. `newsletter/2026-09.md` is the first issue
- everything that decides what an issue says lives in one pure module and is unit-tested, which is what surfaced four ways a naive collector reads this repository wrongly: the 22 preprints renamed in September look like new papers to an identity-only diff; the move of the data tables from `app/_data/` to `data/` empties the comparison baseline and makes the whole database look new; tables written before the current YAML indentation rule cannot be parsed by the site's own parser at all; and rows that carry no date, which is how software and people entries arrive, are dropped by a date filter that assumes every row has one
- an issue states the limits of its own sources rather than hiding them: it says when the snapshot it was built from was taken, and reports citation movement over the window the readings actually cover rather than the window requested
- the network graph's node-click test sampled a small patch of the canvas for something clickable and could come back with a screenful of points all sitting on the same edge, which made it fail on CI while passing locally. It sweeps the whole plot now
- Vitest runs 687 tests, Python validation 38 tests, and Playwright 85 browser tests
