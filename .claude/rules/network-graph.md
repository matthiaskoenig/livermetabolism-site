# Network graph

- **Network graph**: the five research areas are **filters, not nodes** (user decision, see the amendment in the design spec), and only **people carry an image**. `graphRows()` in `site/lib/graphRows.ts` (pure and unit-tested, including tests over the real YAML: 209 nodes, 309 links) projects `data/{tags,people,publications,projects,software}.yml` into the `{ nodes, links }` of the graph — one node per person, publication, project and software row, ids `<type>:<data id>`, each node carrying its `label`, tooltip `detail`, `image` (a person's photo thumbnail, `null` for every other type), `topics` (the research-area slugs it is filtered by; a person's are the union of their publications' tags), `value` (its degree in the whole graph) and `citations` (a publication's count, for the tooltip; `null` elsewhere). Edges: publication → author, project/software → publication, person → project/software, deduplicated per node pair and only between existing nodes. Every `href` is built from the `base` input (`import.meta.env.BASE_URL`) and points at the item's list page plus its detail hash (`people/#person/<id>`, `projects/#project/<id>`, `research/#software/<id>`, `publications/#publication/<id>`), so an href opened directly lands on the list page with that modal open; adding or renaming one of those ids means changing it here too. The only thumbnails are the 61 people photos under `public/assets/image/graph/people/`, written by `npm run graph:thumbs` (`scripts/graph-thumbs.ts`, `sharp`; round, with a 2 px white ring) and committed; a person whose thumbnail is missing falls back to a circle, so a new person only gets a photo node after the script is re-run. `site/pages/[...locale]/network.astro` computes the rows in its frontmatter (the getters plus `loadCitations()` and the set of thumbnails that exist, read from `publicDir` with `node:fs` — `import.meta.url` would point into the bundled prerender chunk under `dist/`) and hands them to the one `NetworkGraph.vue` island (`client:load`, the page's whole content); its intro counts the *drawn* network (`filterRows(rows, null)`), "Network" is a top-level navbar entry (`sectionid="network"`) and every homepage research-area section links to `/network/?topic=<tag>`.

  `networkOption(rows, topic, { relayout })` in `site/lib/networkOptions.ts` (pure, unit-tested, reusing `PALETTE`/`TAG_PALETTE`/`tooltip()` from `chartOptions.ts`) builds the force-layout option over `filterRows(rows, slug)`: the nodes whose `topics` include the slug and the links between two of them (the whole graph for `null`), minus every node left **without a single link** — the view is always a network, which drops 23 people from the full graph. Node `id` is the row id (ECharts resolves a link's `source`/`target` against `id` before `name`, so `name` is free to be the human label); a person is their photo (`symbol: 'image://<url>'`, `symbolKeepAspect`), a project a `roundRect`, a software entry a `diamond` and a publication a circle in its first area's colour (`SYMBOL`), each in its category colour, which is also its legend swatch. Every node is sized by its **degree inside the drawn view** — `min + k·sqrt(degree)`, capped per type (`SIZE`, `symbolSize()`, `degrees()`) — so a filter re-sizes the graph; a publication's citation count only appears in its tooltip. `relayout` (the default) runs the force layout at `LAYOUT_FRICTION` with `initLayout: 'circular'`, which is what a filter change needs; `false` uses `SETTLE_FRICTION` (0), which cannot move a node, so a resize never reshuffles the graph. `useChart`'s `notMerge` accepts a predicate for exactly this: the component passes `() => relayout.value`, so a filter change is drawn from scratch (the layout re-arranges) and a resize merges (ECharts' `preservedPoints` keep every position). `zoom` is `ZOOM_ALL` 0.6 for the whole graph and `ZOOM_TOPIC` 1 for one area. `roam` is `ROAM` (`'move'`, so the wheel still scrolls the page) with `roamTrigger: 'global'` so a drag anywhere on the canvas pans; the zoom and reset buttons go through `roamChart()`/`resetChart()`, and `enableNodeDragging()` (all three in `useChart.ts`) switches roaming off while a node is dragged — without it ECharts' `RoamController` sees a non-draggable image element under the cursor and pans the view instead of moving the node. That `setOption` also rebuilds the series' graphic elements mid-press, so the chart never emits a `click` for a node: `enableNodeDragging()` owns the press/release pair and calls its `onNodeTap` callback when the pointer moved no more than 4 px between them, which is what opens the node's detail modal. The filter buttons are "All" plus the five areas (`.chart-mode-btn.network-topic-btn`, `.active`, `aria-pressed`), `?topic=` (tag name or slug, case-insensitive, unknown ignored) pre-selects one, the resize handler is debounced by 200 ms, and a node click opens that node's detail modal in place (`openDetail()`, the node id is already `<type>:<id>`), falling back to navigating to `data.href` — only when it starts with `import.meta.env.BASE_URL` — for a node type without a detail. The per-area artwork of the homepage sections is `TAG_GRAPHICS` in `site/lib/tagGraphics.ts`, keyed by tag slug, and so are the research-area colours (`TAG_PALETTE`, re-exported by `chartOptions.ts`).
